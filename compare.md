# Error Comparison Script

This document explains how to use the `compare_errors.py` script to compare error analysis results between two retrieval models.

## Overview

The `compare_errors.py` script compares error analysis results from two models to identify queries where one model fails but the other succeeds. This is particularly useful for understanding what improvements a better model brings over a baseline model.

## What It Does

1. **Loads error analysis results**: Reads error cases from both models (generated by `analysis.py`)
2. **Identifies unique failures**: Finds queries where Model 2 fails but Model 1 succeeds
3. **Calculates improvement metrics**: Shows how many errors Model 1 fixes compared to Model 2
4. **Generates comparison files**: Creates detailed JSONL and summary JSON files

## Key Insights

The script identifies three categories of queries:

- **Common errors**: Both models fail (hard cases)
- **Model 2 unique errors**: Only Model 2 fails, Model 1 succeeds ← **Most useful for improvement analysis**
- **Model 1 unique errors**: Only Model 1 fails, Model 2 succeeds (potential regressions)

## Prerequisites

- Run `analysis.py` for both models you want to compare
- Error analysis files must exist in the current directory:
  - `error_analysis_{model1}_{dataset}_{direction}_{split}.jsonl`
  - `error_analysis_{model2}_{dataset}_{direction}_{split}.jsonl`

## Usage

### Basic Command

```bash
python compare_errors.py --model1 "better_model" --model2 "worse_model" [--dataset rfc8205] [--direction c2i] [--split test]
```

### Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--model1` | Required | Better/improved model name (e.g., `jiebi/RFC-DRAlign-LN`) |
| `--model2` | Required | Baseline/worse model name (e.g., `bm25s`) |
| `--dataset` | `rfc8205` | Dataset name (`rfc8205`, `rfc7657`, `rfc8335`, etc.) |
| `--direction` | `c2i` | Retrieval direction: `c2i` or `i2c` |
| `--split` | `test` | Data split: `test` or `train` |

### Examples

**Compare a fine-tuned model against BM25 baseline**
```bash
# First, generate error analysis for both models
python analysis.py --model "jiebi/RFC-DRAlign-LN"
python analysis.py --model "bm25s"

# Then compare them
python compare_errors.py --model1 "jiebi/RFC-DRAlign-LN" --model2 "bm25s"
```

**Compare two different fine-tuned models**
```bash
python compare_errors.py --model1 "jiebi/RFC-DRAlign-LN" --model2 "jiebi/RFC-DRAlign-QN" --dataset rfc8205 --direction c2i
```

**Compare on a different dataset**
```bash
python compare_errors.py --model1 "jiebi/RFC-DRAlign-LN" --model2 "bm25s" --dataset rfc8335 --direction i2c
```

## Interpreting Results

### Model 2 Unique Errors (Most Important)

These are queries where:
- ❌ Model 2 fails to retrieve any relevant document in top-k
- ✅ Model 1 successfully retrieves at least one relevant document

**This shows what Model 1 improves over Model 2.**

### Common Errors

Both models fail on these queries - they represent the hardest cases that neither model can solve yet.

### Model 1 Unique Errors (Regressions)

These are queries where:
- ✅ Model 2 succeeds
- ❌ Model 1 fails

This indicates potential regressions or trade-offs in Model 1.

```bash
# Step 1: Run evaluation for both models

```


## Improvement Percentage

The **improvement percentage** shows what fraction of Model 2's errors are fixed by Model 1:

```
Improvement % = (Model 2 unique errors / Total Model 2 errors) × 100
```

- **80%+**: Model 1 is significantly better
- **50-80%**: Model 1 shows solid improvements
- **<50%**: Model 1 has modest improvements
- **Negative**: Model 1 is worse (more errors than Model 2)

## Troubleshooting

### "Warning: File not found"

Make sure you've run `analysis.py` for both models first:
```bash
python analysis.py --model "model1"
python analysis.py --model "model2"
```

### "Both error analysis files are empty or missing"

Verify the error analysis files exist:
```bash
ls error_analysis_*.jsonl
```

### No unique errors found

If `model2_unique_errors_count = 0`, this means all errors in Model 2 also appear in Model 1. Either:
- Both models have similar performance
- Model 1 might actually be worse (check `model1_unique_errors_count`)

## Tips

1. **Always compare better model first**: Use `--model1` for the improved model
2. **Focus on unique errors**: The JSONL file contains the most actionable insights
3. **Check for regressions**: Review `model1_unique_errors` to ensure Model 1 doesn't introduce new failures
4. **Combine with metrics**: Use this alongside overall HIT@k scores for complete picture
5. **Iterate**: Use comparison results to guide further model improvements
